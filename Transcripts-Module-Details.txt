web page that provides the basic content and the structure. Think of HTML as the skeleton of
the webpage. It has the content to be displayed, but in a very rudimentary form, and it structures
it into headings, paragraphs, lists, sections, giving the browser an outline of how the page is
structured.
If you visit a blog, the HTML file holds the main text of the article, but along with elements

and it has the ability to control everything.

HTTP Request
Hi, everyone. In our last few videos, we spoke about how computer requests files from a server
to load a webpage and how the server responds with the files, namely HTML, CSS, JavaScript,
which are then rendered by your browsers to show you information. In this video, we will go
deeper into this request response cycle, understand the role of HTTP requests, and then also
learn what is front end and back end.
Remembering our last video, when you type flipkart. com in your browser, your browser
requests files from Flipkart's server. The server processes this request and responds with
HTML, CSS, JavaScript, and other resources that make up the Flipkart website. The browser
then takes these files, interprets them, and displays the web page in front of you.
But while there are so many websites and servers, how do we make them talk and understand
the same language or in the same grammar? How do they send information in correct format
that can be understood by any browser? How can servers send files that can be understood by
any browser? How can browsers ask for files that are understood by any server?
This is where HTTP comes in between. And HTTP request is one type of request that your
browser sends to the server. HTTP stands for Hypertext Transfer Protocol. It is a set of
instructions or protocol or grammar that defines how data is sent and received over the internet.
HTTP allows browsers and servers to communicate effectively, no matter which device or
which network they're on.
But HTTP is just one type of protocol. There are other types of protocols, such as HTTPS,
which is a secure version of HTTP. FTP which is the file transfer protocol SMTP or the simple
mail transfer protocol. Each protocol serves a specific purpose and defines the grammar or the
instruction to be used while communicating between different devices.

Frontend and Backend
Frontend and backend. What do they mean? Now that we know about request response cycle
and HTTP, let's talk about frontend and backend, the two main sides of a web application. What
is frontend? The frontend is everything that you see and interact with in your browser. It
includes layouts, colors, fonts, images, buttons, and more.
Front end development uses languages such as HTML, CSS, and JavaScript to create and style
this element. Think of the front end as a user interface. It is designed to look appealing and
provide a smooth experience. When you click on a button, scroll through a page or watch a
video, you are interacting with the front end.
What is the backend then? Backend is everything that is happening behind the scenes. It's where
data is stored, processed, managed, and retrieved. Backend is responsible for tasks like
retrieving data from databases, handling user logins, and processing transactions. Backend
development typically uses languages such as Python, Java, Ruby, or even frameworks based
on JavaScript like Node js. The backend powers the features that the frontend presents to the
users. Why is backend primarily needed for heavy applications? Not all websites need a
backend. Backend functionality is generally required for heavy applications that rely on
complex interactions and data processing. Like social media platforms, e commerce stores, or
even streaming services like Netflix.
For example, a simple website like IIMB DBE website can be built with just the front end to
display text, images and information. However, if you want advanced features like user login,
course tracking, or if you want to present personalized data as in the IIMBx e-learning platform,
then you need a backend.
The backend would handle data storage of all these files and elements, authentication of users,
user management to support these functionalities. And much more for many businesses front
end alone is enough to provide an attractive and informative website for customers. What is
the focus of this course?

Evolution of Internet and its Impact on Businesses and Daily Life
Hi, today we are going to discuss the evolution of internet and its impact on businesses and
daily life over the years. We will see how digital innovation has transformed the world since
the 1990s, both globally and here in India. The beginning of digital age. The internet as we
know it began in the early 1990s, thanks largely to Tim Berners Lee.
Before this, networks existed, but they were mostly limited to research institutes and
government use. Tim invented HTTP and HTML, the core technologies that we introduced in
the previous videos. These were foundational technologies that enabled people to access and
share information online. His work laid the infrastructure for internet and created the World
Wide Web as we know it today.
In the early 1990s, websites were basic and text based with limited interactivity. Popular early
browsers like Netscape Navigator and Internet Explorer helped people explore the web, but it
was mostly static content. Businesses saw the potential and rushed to establish an online
presence. This led to the dot com boom and everyone scrambled to block domain names and
build businesses. Some examples are peck.com and boo.com. There was extreme excitement
about internet's potential. Venture capitalists poured money into any such venture. Assuming
that all of these would become global giants.
The dot com boom and bust. As internet gained popularity, the late 1990s saw rapid growth in
internet bound businesses. The dot com boom was born, as companies saw internet as a new,
exciting market. Many rushed to launch websites, assuming that any dot com would make
money. But around the beginning of 2000, The dot com bubble burst, leading to a huge market
crash. Companies built on hype and lacking substance quickly disappeared.
However, companies with real use cases and purposes thrived. Businesses like Amazon and
Google flourished because they offered real value. The sites that survived and eventually
prospered after the bubble burst had two common things. A sound business plan and a niche in
a marketplace that either was unique or particularly well defined and well served.

Product Management Principles
Hi, welcome back today we are diving into how product management principles can transform
the way we approach web development. Before anything else, let's ask ourselves two
fundamental questions. Why is a website needed and what do we want to achieve with it? These
first principles questions help us understand the core purpose of a website.
A successful website isn't just about aesthetics. It's about meeting business objectives while
delivering a stellar user experience. By approaching design and development fundamentally,
that is understanding both business goals and user needs, you can create websites that are not
only functional, but also impactful.
Let's explore how structuring, prioritizing, and balancing goals can help us achieve this. First,
we must structure website based on business objectives. Every website should have a clear
purpose, whether it is to drive sales, to generate leads, or increase brand awareness. Structuring
your website around these objectives ensures every element serves a purpose. For example, if
you are in Flipkart, the business objective is to drive e-commerce sales. Therefore, you should
structure the homepage such that it highlights sales and offers. Product categories must be
prominently displayed for easy navigation. Put user ratings and reviews to build trust and
encourage purchases.
Everything is towards the business objective of driving e-commerce sales. So to apply this, you
need to define the primary goals, ask yourself, is it to sell? is it to inform or is it to engage?
Then you design the user journeys, map out how a user will navigate to reach the goal. In case
of Flipkart, I can land on the page.
I could land through ads on a specific product. After that, so if I land on the main page, I need
to go through the categories or through the search. Then I need to go through the subcategories
pages, look at various product pages, then click on add now, then go to the cart, then add a
payment method, add a address, and then complete the purchase.
